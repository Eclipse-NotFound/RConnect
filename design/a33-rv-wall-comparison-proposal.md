# A33 密集场景的 RV 墙面比较优化提案

状态（2026-10-16）：用户已批准本提案。局部实现与隔离图像验证完成，RV 源码提交 6108930；518 项独立检查、153 项原生场景检查及 32 对画面/雾层精确比较通过。完整组合的密集场景仍未过原门槛，因此尚未部署。RConnect 的念力和 SATS 修复继续独立验证；下文保留原批准范围。

## 实际证据

当前组合 runtime17，RConnect fix32；隔离运行 `28ab1a49f6`。这是带 CPU 采样的诊断，不是性能验收。
- 主侧 2413 个 CPU 样本中，451 个经过 `RVWallSurface.update`；加入侧 1871 个中有 452 个。
- 其中墙面比较里的数组拼接及其内存回收，主侧约 215 个、加入侧约 214 个。源码每次更新都会把整块几何、探索标记、亮度数组变成长字符串，然后比较是否变化。
- 最新无采样密集验收 `7517f6fe82` 七窗只有 54–60 帧/8 秒，仍未达 80 帧和 P95<200ms 的门槛。这些采样不能证明单独改 RV 就能解决全部卡顿。

## 具体修改边界

仅涉及 `RealisticVision/src/RVWallSurface.as` 的变化检测及其初始化/清空：
1. 几何仍逐格调用原 `heightAt`，与已保存的高度值直接比较；完整扫描和光照调用频率保持原样。
2. 每个墙面的探索标记、原量化亮度直接逐项比较，并保留相同顺序的数值给原绘制代码使用，省去三个 `join` 和大量临时字符串。
3. 换房、视口尺寸/位置、面数量、常亮开关变化时完整失效；异常中断后必须失效，不能让半次更新被误认为已完成。
4. 亮度 NaN 等边界按旧字符串比较语义处理；不把非有限数悄悄改为 0。

不涉及视野规则、墙面亮度、灯光、遮罩层级、同步频率、原生 SWF 或 WallBlend。已安装 RV 字节为 `baa48289d9cf86f64cff53b4734032ad29c89c3ac1704db2d89038d4b8db4275`。源码指纹：`d5142d3d9d9885b804628cf7ac12c4fa9320c48c33dd62bf1101759dc8a2b7fd`；实施时须与 RV 开发会话核对准确部署线，不能直接覆盖其其它工作。

## 验证及回退

先构建隔离候选。把新旧变化检测对同一批几何/探索/亮度输入逐项比较，覆盖不变帧、单格破墙、亮度、已探索标记、切换模式、换房/视口、非有限输入和中途异常。再用同一原生场景比较实际输出位图及常亮开关行为，最后运行不采样的相同密集场景。只在图像等价、收益得到实际验证且原门槛通过后考虑替换正式 RV；备份并保留单模组回退。不能据代码推测宣称提速。

最坏情况：失效条件遗漏可能让墙边残影或亮度停住，因此必须先做逐像素与场景切换对照；无法证明等价时保留原版。
