# B 架构：RealisticVision 本机显示隔离接口提案

2026-10-12；状态：等待用户授权，未修改 RealisticVision。

## 已观察到的问题

敌人回归 083（2aac2f0bb696）双方完成，无运行时异常；加入侧有三个阶段敌人身体样本不足，其中炮塔、旋翼机为零。原生资源与已采到的身体、护盾、武器、血条逐帧对照没有像素错误。

源码证据：RealisticVision 的 hideUnit/showUnit 会直接写原生单位 vis.visible、hpbar.visible、prior；setWeaponVis/scanArms 也会写武器和外接部件可见性。B 下一次主侧采样可能读到宿主上一屏的遮挡结果。当前测试证明存在采样缺口，具体修复仍须双视角隔墙实测，不把代码推断当作最终根因。

## 建议的精确改动

只在 RV 自有的显示处理入口增加保存/恢复：

1. 在 RV 首次改变每个单位/武器/外接部件的 visible、mask、cacheAsBitmap 和单位 prior 之前，保存 RV 介入前的值。
2. 在现有 RVExplorationAPI 上增加可选的 prepareSimulation(room) 回调。B 在主侧原生世界步开始前调用，使原生模拟和网络采样看到真实动作状态。回调只恢复 RV 自己保存并改动的显示值，不改变战斗、地图、探索历史、亮度和视线计算。
3. RV 每屏照常按本机玩家计算遮罩；加入侧也用自己的视点。普通单机和 A 不调用新接口，沿用原流程。
4. 房间切换/敌人删除清理相应记录；采用弱引用防止死亡实体保留。重复调用安全，不让旧记录覆盖新实体。

B 的调用与缺接口提示留在 RConnect；RV 的字段保存/恢复留在 RV，避免 RConnect 猜测其私有字典或复制整套视野算法。

## 隔离验证与影响范围

- 仅构建隔离 RV 副本并与 B 配套测试，安装版 RV、A、游戏本体不动。
- 主侧/加入侧分站实墙两边：各自敌人只在正确视点出现；换位、破墙后恢复；血条、武器、狮鹫手臂同时检查。
- 原生隐身、尸鬼钻地、未发现地雷、死亡消失不得被无条件显示。
- RV 未 attach 的单机/A 行为、探索接口、暂停/换房、可见性扫描性能做对照。

这是对 RV 的新接口权限，不属于此前已允许的探索编码局部缓存优化，也不同于尚未获准的可见性扫描缓存优化。若获准，可就此接口与 RV 开发会话协调；不扩大到其它功能。
