# 用 TCP 内网穿透远程联机

[English](tcp-tunnel.md) · **简体中文**

适用：RConnect A `0.2.24-tcp1`，Windows / Remains 1.02。双方安装同版并重启。无需更改战斗同步协议；穿透工具负责把队友的连接转发到宿主游戏。RConnect 不代办穿透账号、节点或服务器。

## 最短设置流程

假设宿主的游戏端口是 **23456**，穿透工具分配的地址是 **node.example.net:45678**（示例，需换成自己的地址）：

| 在哪里设置 | 填什么 |
|---|---|
| 宿主 RConnect「端口」 | `23456`，然后点击「创建房间」 |
| 穿透工具的隧道类型 | **TCP** |
| 穿透工具的本地地址 | `127.0.0.1`（穿透工具和游戏在同一台电脑时） |
| 穿透工具的本地端口 | `23456`，与宿主游戏一致 |
| 穿透工具的外部／远程端口 | 服务分配的 `45678`，不必与本地端口相同 |
| 加入侧 RConnect「宿主地址」 | 粘贴 `node.example.net:45678`，点击「加入」 |

加入时会自动分开域名和端口，回填两个输入框。也支持 `tcp://node.example.net:45678`；或地址填 `node.example.net`，端口单独填 `45678`。地址里明确写了端口时，以它为准。主侧创建房间只使用端口框的本地监听端口，地址框不参与监听。

**不要让异地队友填写 127.0.0.1**，那代表队友自己的电脑。宿主需保持游戏和隧道同时运行；普通 TCP 转发下，加入侧只需游戏，不用运行宿主的穿透客户端。先载入双方角色，再连接。

## SakuraFrp

在穿透工具中建一个 TCP 隧道，本地地址／端口按上表填写，启动后复制日志给出的连接地址，交给加入侧粘贴。节点和远程端口使用实际分配值。依据：[官方其他游戏联机说明](https://doc.natfrp.com/game/other-games.html)。

## 自建 frp

在已完成服务端连接和认证的宿主 `frpc.toml` 中加入以下代理段；外部端口须由你的 frps 服务器允许使用：

```toml
[[proxies]]
name = "rconnect"
type = "tcp"
localIP = "127.0.0.1"
localPort = 23456
remotePort = 45678
```

加入侧连接 frps 的公网域名／IP 与 `45678`。上述只是代理段，不包含服务器地址和账号凭据，也没有替你创建公网服务。配置字段依据：[frp TCP 转发](https://gofrp.org/en/docs/features/tcp-udp/)。

保持普通 TCP 字节转发；**不要开启 Proxy Protocol 头**，RConnect 不解析此头。也不要选 HTTP/HTTPS/UDP 隧道或把网页访问链接粘到游戏中。Proxy Protocol 会在游戏协议之前额外发送头部，见 [frp 代理配置](https://gofrp.org/en/docs/reference/proxy/)。

## 连接不成功时

1. 先确认宿主已创建房间，游戏内端口与隧道本地端口相同。
2. 确认隧道显示在线。若日志显示无法连接本地服务，先排查宿主游戏／本地地址／本地端口。
3. 加入侧使用隧道分配的外部端口，不能照抄宿主的本地端口。
4. 若隧道能接通但游戏握手失败，检查双方版本和是否误加 Proxy Protocol／网页代理层。
5. 转发会增加延迟，节点上行不足也会卡顿。本次适配不承诺修好已有密集战斗、弹道和房间加载卡顿。

当前 RConnect 没有房间口令和应用层端到端加密；地址只给可信队友。长期公网开放时，应在穿透服务端限制可连接来源或使用其私有访问功能。不要把穿透账号令牌发给队友或填进游戏地址框。

## 已验证与尚未验证

已完成的证据见[本版发布说明](release-0.2.24-tcp1.md)：本机独立双实例经过真实 TCP 转发、内外端口不同、域名解析、界面粘贴地址、Unicode 聊天与游戏状态包。延迟／拆包测试仅代表模拟条件；没有使用你的穿透账号、真实公网节点或第二条宽带完成异地长局测试。IPv6 地址格式可解析，但未据此承诺 IPv6 隧道已实测。
