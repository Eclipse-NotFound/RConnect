# Q 使用队友视野（独立候选）

本功能基于准确冻结的 `build/m52/a22-fixes-39`，由 `tools/validation/prepare_peer_vision_port.py` 加入三个小接点：RConnectMod 初始化、Config 默认值和 NetHud 队友页。当前其他会话的房间/手雷/安保修改不参与构建。

玩家入口：浮窗 → 队友 →「Q 可用队友视野」。默认关，由宿主统一设置；加入侧显示宿主当前决定。离线可预设，实际扩展权限仅在双方同房且完成同步时生效。不会改变原版自己可传送的位置。

实现：按 Q 时只向队友询问鼠标目标瓦片。答复必须属于当前连接、房间、交接批次和开关版本，且从发出询问到使用不超过350毫秒；新答复否定后不恢复旧肯定。离房、断线、死亡、同步暂停、关开关均清掉权限。旧版队友没有答复时不会开放目标。

视野：不读取共享探索的历史并集。原版 Tile.visi 在部分地图也会保留历史，因此再以原版 Location.lighting 的距离衰减、墙壁及水透明度检查目标当前是否明亮。每次仅算一个点，不更新地图、不重绘视野。

施法：原版先处理真实的 Q 蓄力和松开；只在本帧消耗了非零完整蓄力、原版因本地视野拒绝、队友权限仍新鲜时，调用原版 actPort。只在该同步调用期间临时补足目标一格的 visi，finally 恢复。耗蓝、冷却、碰撞、受电区域、念力释放和动画均由原版执行；没有第二套传送伤害或耗蓝公式，也不修改游戏 SWF。预览同样调用原版 showPortCel 并立即恢复借用标记。

测试源在 tests/PeerPortTestDoc.as：实际游戏中双向按住/松开 Q，检查开关、自身/队友视野、历史区域、遮挡、缺蓝、短按、冷却、无技能、失去视野、关闭开关以及原版落点/耗蓝/预览。生产与驱动分开编译，真实存档不写。编译成功不能代替原生用例通过；当前进度见模组 state 中本功能记录。
