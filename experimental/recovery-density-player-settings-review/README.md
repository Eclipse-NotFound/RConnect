## 弹体计数的语义边界

六段开火均见可用轨迹及移动显示，但新旧表示不同：574D 普通 NPC 弹体用原生出生、速度和终点；20 的 UnitPresentation 把普通弹也记录为实际帧轨迹，ProjectileVisuals 在源终点结束，并只插值已确认的相邻段。

driver 的 events 是每份 unitsync 中出现的记录次数，没有按弹体 ID 去重，也不统计更快的 effects 通道；visible/moving 是每个 RENDER 的对象采样次数。同一弹体会反复计数。因此 574D 六段 recordedFrames 全 0，而 20 为 2584/2792/2736/2768/2775/2832；不能把 events 增多解释为真发射增多，也不能把 visible/moving 较少直接解释为丢弹。六段 endedSamples 均 0，只说明所收帧没有越过记录的 end；对不含帧数组的旧格式，这条检查不能证明真实寿命一致。这组数据不提供逐弹匹配、命中尾帧或首显延迟资格。
