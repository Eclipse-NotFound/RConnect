# B190 field fixes

本覆盖源只应用于 `build/ab/b190-startup2-build` 的准确冻结源。它不是 `experimental/host-authority/src` 当前开发头，也不包含 B195 的未验证改动。

## 构建与范围

`tools/host_authority/field_driver/prepare_fix.py` 校验冻结基线，将完整 src/stubs 复制到指定 build/ab 新目录，再覆盖这里的九个源文件。`compile.py` 通过共享登记编译到另一个新目录，保留完整源码、编译清单和哈希。

产品变化：

- 延迟换房提交之前，原生玩家本帧剩余碰撞仍在旧房有效边界内运行。目的房、速度和帧尾统一交接保持原协议。
- 加入侧使用确认后的对象位置选择鼠标目标，由原生 GUI 显示名称、锁定、按键与成功率。容器及掉落只读地重建 Interact 数据；行为仍提交给主侧。
- 保留相同视觉数据，减少矩阵/颜色数组及类型检测；指向候选去重改为线性；已有完整血条快照时避免立刻被覆盖的原生重复布局。
- 加入侧缓存固定公开存储字段的存在性，只有实时值确实相同时跳过重复写入；动态字段与设置器保留原路径。零始终写入，避免正负零被错误合并。

## 审查边界

- RoomTransfers 的修正只处理方向 1–4；背景门 5 不改变。只对已接受/已排队的换房夹住旧坐标；拒绝的门沿用原行为。
- 原生 Interact 构造会增加对象 priority，所以随后恢复主侧字段；不调用它的 step/actFun，不把掉落提示代理加入物理链。
- 新提示字段为现有 Loot 元数据的增补；旧的弹道、粒子、原生动画及死亡协议未删减。
- 缓存只复用相等且不可变的数据；动态 Object/* 仍按实际类型过滤，Number 仍排除 NaN/Infinity。冻结前后语义与编码往返由独立参考路径检查。
- 血条保留首次创建、缺失快照与 boss HUD 原路径；常规敌人的完整血条外观以主侧快照为准，需敌人图像回归验证。
- 字段写入的对照检查包括本地值被改动、动态字段新增/移除、设置器连续调用与正负零。只缓存“字段属于普通存储槽”的结论，不把上一份网络包视为当前本地值。

性能结论以相同工作负载的准确字节实测为准。源码更短或单轮变快都不构成稳定收益；不削减同步频率、敌人数、伤害结算或关闭玩家所用模组来制造本轮收益。

当前资格与实际安装见 `state/B-MEMORY.md`；所有失败保留在 build/ab 的原结果目录，不重写为成功。
