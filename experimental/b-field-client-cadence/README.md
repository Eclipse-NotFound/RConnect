# B 加入侧插值索引候选

2026-10-28。以 `build/ab/b190-field8-loadfix1-build/src/authority/PoseTween.as` 为准确基线，**仅源码候选，未编译、未运行游戏、未测性能，不可直接部署**。根会话负责合并和验证。

第一处产品改动是 `PoseTween.keyed`：对同一个不可变确认数组，按索引字段 `id` / `key` 分开保存查询表。后续对同一个后继确认帧插值时可复用，避免反复遍历并构造相同索引。仍按原顺序处理重复编号，最后一条覆盖先前条目。空值不缓存。新的数组身份始终建立新表。

缓存使用弱键 Dictionary，值只保存记录和查询表，不保存输入数组本身。依据是 FrameDelta.decode 的旧确认分支不可变契约；此缓存不能复用到原生单位列表或可变临时数组。实际收到的数据不存在指回父数组的循环；没有新增全局最近帧引用，旧队列不因键而保留。此为静态引用关系核对，不是实际GC/内存测试。

不改 VisualPose、显示状态写入、玩家预测、消息顺序、物件生命周期、播放时钟、网络频率和帧内容。也没有将未知的本机显示树假定为不变。旧 `b-field-motion-fixes` 的 motion18 已失败且无收益，本轮不复用该轻量显示导入方案。

外部检查位于 `tests/BCadenceChecks.as` 与 `BCadenceReferenceChecks.as`。后者是冻结基线 PoseTween，保持原先未缓存的 keyed 遍历，仅更名并把未改动的 NativeFields/HealthBarPose 引用改成动态解析，供独立测试SWF调用。本次没有在AS3中执行这些检查，不能称通过。

接入现有外部驱动时复制两个 `B*Checks.as` 文件，实际候选加载后调用 `BCadenceChecks.run(domain, check)`。检查包括多次插值、同数组同时按id/key索引、重复key与顺序、换数组同ID、旧帧不变、全部场景集合、缺失/空索引、离散地形/事件保持原引用、暂停/房间/时停边界。对照比较整个返回结构，另有关键字段的独立预期值，不能用同一个新算法作为自己的预期。

收益边界：只在同一个后继数组被多次使用时避免建表。下一确认帧供应不足、每帧后继数组都变化、原生显示导入或渲染本身过慢时，未必有可测收益。需要根会话的 PoseTween 段计时和真实加入侧前后对照。

## 解码路径前缀复用

根会话细分计时后追加 `FrameDelta.decode` 的独立候选：同一包内连续操作保留到上一次**写入容器**的路径栈，下次只从相同前缀末端继续。每次写操作前截短到目标容器，因而不能持有刚被替换/删除的子对象；根替换立即清空并指向新根。实际每个新增路径节点仍使用原来的 writable Dictionary 判断、按当前父路径克隆，不改协议、操作顺序、encode、分组更新/删除和异常序列检查。路径键以严格相等比较；数字与字符串形式不同只会少复用，不能换错节点。

不变量：缓存的 parents[0..depth] 是当前 prior 下 prefix 的真实容器链。每次旧算法只会写 target 自身的成员，所以保留至 target 的链仍有效，任何后代都被丢弃。下次公共前缀只引用这条有效链；剩余部分逐句执行旧算法。根替换单独重置这一不变量。
