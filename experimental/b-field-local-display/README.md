## 本轮实现范围

这是低传输压力显示分工的第一阶段：减少重复描述和应用，不增加第二份战斗模拟。当前不实现全部身体、武器或任意粒子的自主播放。

| 改动 | 主侧工作 | 加入侧工作 |
|---|---|---|
| 已知原生血条的专用描述 | 读取实际显示帧、显隐、位置与必要样式；未知结构回到完整显示快照 | 根据专用描述更新本机原素材，保留血条子节点插值；不重新计算私有护盾上限 |
| 原生伤害数字的模板复用 | 静态文字模板首次/变化时采集；持续发送确认的根位置、透明度等 | 模板不变时只应用根显示状态，按现有统一时间线插值；不创建会执行游戏逻辑的Part实体 |
| 弹丸发送投影 | 仅在发送副本中筛选加入侧显示房间的弹丸和生命周期事件 | 不再解码最终不会显示的另一房间弹丸；当前房的出生、结束、短命弹丸和可抓取身份保留 |
| 源码及协议身份 | BuildInfo revision升为5，源码指纹保留为构建模板 | 使用原严格握手，不能与field5/6混连 |

伤害数字覆盖限制为准确的`fe.graph::Part`与已知`visualNumb`结构。NPC气泡、烟火、图集动画、延迟/水面粒子、掉落、投掷物、未知素材与时停回放均沿旧路径；没有把全部“纯装饰”一概视为安全。累加伤害会更新同一数字，必须仍能刷新其文字模板。

这轮没有把数字改成按本机墙钟自行跑完寿命，也没有新增“每帧询问下一张画面”的往返。位置和透明度仍受已确认画面控制，因此原播放缓冲、共享暂停和时停节奏保留。收益来自少做通用显示树采集/应用；实际CPU、字节量与延迟变化未知，原本的FrameDelta已经会省略未变化数据，不能把所有静态模板字节都算作新增节省。

## 保留的正确性约束

- 战斗AI、物理、命中、伤害、地形、掉落、两房状态仍只由主侧运行。
- 原生枪口依赖武器显示节点，主侧武器动画及枪口计算没有关闭；原生帧脚本也没有在加入侧重新启用。
- `VisualPose.captureRoot`有独立的弱缓存，不覆盖完整树或时停像素快照的缓存；所有传输记录仍不可变。
- 紧凑血条/数字与完整显示路径可切换；子节点变化和本机显示修改不能因缓存被忽略。
- `HostSession.lastFrame`和`RoomRuntime`保留全量两房记录，只编码独立发送副本；抓取记录以实际发送内容为准。筛选使用显示房`frame.room`，不用可能处于另一时间的实时控制房。
- 无换房额外交接，没有删除同tick出生又结束的弹丸，没有降低同步频率或更改输入/播放时钟。

## 文件与后续组装

`source-manifest.json`固定基线、继承候选及本次覆盖源的指纹；`changes.patch`是相对准确scalar04的完整差异，`field7.patch`只列出相对field6的新增变化。新模块也在这些差异与清单内。冻结的field5、field6和安装文件均不改。

`prepare.py`只准备新的`build/ab/b190-local-display*-source`源码目录，不编译或启动任何程序。本轮保存了该配方，但没有执行。新增的`BuildInfo.as`已使用`__SOURCE_HASH__`模板，避免把冻结构建的旧指纹带入下一次构建。未来获准验证后再组装/编译，不能直接把本目录当作已验证SWF。
