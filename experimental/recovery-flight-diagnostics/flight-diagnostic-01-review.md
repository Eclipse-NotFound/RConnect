## 最强证据：加入侧缓存容量小于循环工作集

| 观察 | 主侧 | 加入侧 |
|---|---:|---:|
| 不同 payload（按完整原字符串） | 33 | 82 |
| 不同解码数组（按解压正文 SHA） | 33 | 82 |
| 总 words / 原字符串字符 | 40,774 / 110,568 | 99,060 / 298,328 |
| 缓存命中 / 未命中 | 13 / 34 | 1,147 / 1,276 |
| 驱逐次数 | 8 | 1,246 |
| 重置次数 | 0 | 0 |
| 未缓存的 protectedPixels 解码 | 0 | 122 |

所有 payload 均是合法的数值稀疏格，全部符合当前缓存条件；加入侧只有同一个 WallImpactVisuals 实例（诊断 id 12）。**每次驱逐的原因位都是 2，即 32,768 words 上限**，没有一次由 64 项或 131,072 字符上限直接触发。结束时仅保留 30 项 / 32,716 words / 103,876 字符。

这不是同一内容换了压缩字符串，也不是 reset 或校验失败。许多大格在完全相同的字符串上解码 13–15 次；payload 51–55 各解码 27 次。FIFO 保留量约 26–30 格，后续遍历又要用到已驱逐的格。只改 LRU 而保持这个 words 容量，无法容纳本轮循环工作集。

加入侧 case 0–7 的 miss 次数依次为 **221、148、133、154、119、166、172、163**。只有 case 0 出现 protectedPixels 的 122 次，后七轮仍有大量重复解码，所以不只是第一次建立场景的成本。

本轮加入侧 1,398 次 unpack 的计时：解码至第一行日志前 1,629 ms，第一/第二行日志 1,288 / 1,050 ms，总调用 3,977 ms。WallImpactVisuals 外围测量合计 3,989 ms（含少量插点/边界差异）；其中普通 miss 3,658 ms，protectedPixels 331 ms。主侧 169 次 pack 共 678 ms、34 次 unpack 共 104 ms，全部发生在 case 0。

建议最小候选只扩大有界缓存到 **128 项 / 131,072 words / 524,288 UTF-16 字符**，保留当前解码、合法性、版本检查、返回新数组和 reset 语义。该容量容得下本轮完整 82 份内容，但不是所有地图都不会驱逐的保证。按 8 字节数值槽和 2 字节字符估算，三个上限中的主要数据容量由约 512 KiB 增至约 2 MiB，增加约 1.5 MiB；AS3 对象/数组和字典开销另计，不能冒称实测堆增量。应以实际旧/新生产类回放真实 payload，比较解码调用数和输出，再跑原八轮，不改门槛。

`presentationTiming` 的函数范围是 onVisForceFrame 主体和 tickFrozenAnims，**不包含整个 Session 接收、墙面更新、RoomSync、其他模组、调度等待等**。本轮主侧 view 总计 649 ms / 1,722 次，最大单括号增量 3 ms；加入侧 view 727 ms / 1,416 次，最大 4 ms；加入侧 motion 1,003 ms / 708 次，最大 14 ms（闪电轮）。因此不能把一个 140 ms 整帧空档叫作“插值函数用了 140 ms”，也不能由这两个计时很小推导整个 RConnect 很轻。

明确的未归因部分：加入侧 case 4 的 `65847→65988` 为 141 ms，127 ms 在最后 RENDER 和下一帧之间，期间 **无 wall decode、无 codec、view/motion 增量均 0**；发生在 evaluate 后、下一轮 prepare 前。它不是本轮飞行间隔失败的直接样本，也不能用缓存或日志解释。其他回调括号亦偶有 70–84 ms，不能直接归为 RC 自身。当前统计是 getTimer 墙时，不是 CPU 采样。

像素核对不是零成本：本轮各轮首显/接触测量通常 14–31 ms。首次可见时先记时间后采像素，它会延迟后续帧，但上述 case 2/4/6/7 最大可见间隔当次都没有像素采样，不能把它们统一解释为像素夹具成本。
