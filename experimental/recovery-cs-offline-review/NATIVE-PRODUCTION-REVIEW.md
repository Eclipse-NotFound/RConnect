# 正式无 RC 诊断 API 对照：独立只读核验

2026-10-23。核验 CS 的 `knowledge/experiments/evidence/rc-native-20261023-baseline-r1`（A）和 `rc-native-20261023-candidate-r1`（B）。本次未修改 CS、冻结生产或驱动，未启动 AIR。

**结论：记录支持“本次独立进程场景中候选总体更快”，不支持把差值全部归于 RC、声称完全同一世界，或授予整体性能/发布资格。** 两臂均为 90/90 检查通过、完整 1200 个连续帧间隔；五个顺序块平均值和 P95 均向好，但候选最大单帧更长，自然人口、AI 开火及地形更新工作量也不等。

## 配对限制与功能范围

玩家射击计数均为 400（每块 80）；敌方为 810/884，两臂全部 20 段都实际检测到双方射击。90 项原断言名称一致且全部为 true，包含每段活着的六名武装敌人、同一逻辑地图、无空白视口和玩家实际开火；它们不是逐像素画面一致或所有武器功能验证。

布局种子均为 20261019、尺寸 240×125，入口/选中房间/104 格走廊哈希相同。但自然生成单位数量为 **147/149**；第一段 census 的 UnitMerc 为 **23/13**、UnitZebra 为 **1/11**、UnitSlaver 为 **17/19**，已直接证明人口组成不同。分段末清醒对象范围分别为 36–48 / 39–50；预热 695/750 帧，敌方预热射击也不同。六名测试敌人相同不能抵消这些自然人口差异。

测量期地形 warm slices 合计 **40/22**，resident 从 125→134 / 123→128；两臂 forced、misses、empty 均为零。故相同初始选区哈希不证明后续地形加载、视口位置和破坏工作量完全相同。B 开火更多也不能抵消它地形更新更少所形成的混杂因素。

每臂仅一次进程、A 后 B，五块是同一进程的连续分块，不是五次独立配对。两个 process-policy 均记 private desktop、无其它 AIR，但均 `performanceEligible=false`；summary 也保留 `performanceAcceptance=false`。证据可支持继续候选回归，不能替代真实双人、不同地图/画面设置、生命周期及长期性能验证。
