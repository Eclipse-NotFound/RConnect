## 首帧与新增采集成本

没有宿主 `flushPausedWorldState/broadcastWorldState` 的逐调用耗时或区分补发／定时发送的计数；故无法单独测得新增采集耗时，也不能从原生日志证明每一次边沿守卫均通过并确实补发。

只在 pauseTiming 保留完整 ENTER-begin→首个 paused RENDER-observed 的轮次计算加入端本地跨度：

- 两版都完整的 round1：69→81ms；其中现有 view 累计计数增量 19→27ms，motion 2→0ms。
- 两版都完整的 round7：59→65ms；view 均 23ms，motion 均 0ms。
- 其余只在一侧完整：22 round6 为 62ms；23 round4/5 为 61/65ms。缺少起点的轮次不以环内第一条替代。

这两组共同首帧跨度在 23 更长，但它们是**加入端本地帧边界**，不是宿主额外采集的时间；view/motion 也仅是已有局部计数，不能解释整个跨度。完整去重轨迹最大相邻间隔 22 各轮为 120/96/96/99/97/90/102/88ms，23 为 101/100/110/80/86/92/93/90ms，同样不显示一致方向，不能宣称“没有可见回退”或“已经显著优化”。

## 比较边界

两轮都使用相同固定地图种子并移除环境敌人，但准备时记录的被移除数量为 9→6。两轮都完成移除，这个差异本身不能证明计时中仍有额外敌人；驱动没有完整静态场景指纹，因此也不能证明全部剩余对象完全一致。每轮宿主实际行走帧数分别为 63/64/64/59/60/61/61/64 与 66/66/63/62/63/67/61/62，端点相应变化。这是相同场景流程的一次实际运行对照，不是逐帧输入回放或完整性能因果试验。
