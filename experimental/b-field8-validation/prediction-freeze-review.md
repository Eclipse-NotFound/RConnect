# 150ms 预测超时冻结：静态边界复核

2026-10-28。复核对象是 `build/ab/b190-local-display-field8-source/src/authority/MovementPrediction.as` 的 `held` 修改及现有接收、输入、原生坐标路径；没有因此启动游戏或修改产品。

判断：按“超时后只保留已经显示的绝对位置，不再模拟前进”的契约，未发现会改变权威战斗、碰撞、瞬移，或扩展原 24px 预测走廊的实际路径。此前把停止、反向输入仍保留缓存称为安全缺口不准确，撤回该判断。

- `held` 只来自成功的 `GroundMotion.advance`。每个完整步都检查 `left/right`（主侧位置 ±24px），分数步在两个已通过边界检查的位置间插值；超时分支不调用 `advance`。
- 多次 `applyPlayer`、原生 `Unit.setPos` 与 `VisualPose` 都写入绝对坐标，不会逐次累加位移。`setPos` 只更新坐标、包围盒和无目标 `setCel`；`setVisPos` 只更新显示变换。
- 加入侧 `before` 保持世界暂停；`InputSource`、`Commands` 传送按键、瞄准点和动作，不传送加入侧预测 X。主侧交互与技能仍使用主侧实体位置。
- 每个新确认先清空 `held`。身份、房间、位置代次、地形版本、暂停、无可预测运动、不安全输入或待确认输入超过 64 项，都会走既有清理路径。回放开始与结束的确认也先清空缓存。

限制：超过 150ms 没有新确认时，松手或反向输入可以继续保留同一个显示 X；这不继续沿旧方向移动，也不执行本机物理，但不会立刻显示新的制动或反向运动。只有显示连续性受到保护，不能称为“输入立即生效”，也不解决主侧长帧或真实网络等待。新确认仍可作真实纠偏，不能把其位移差异一概当成可隐藏的抖动。

上述是代码边界复核，不替代冻结候选的运动和性能实测。后续结果应分别记录真实预测次数、绝对 X 是否继续推进、暂停/瞬移边界及新确认纠偏，不能只看镜头反转计数。
