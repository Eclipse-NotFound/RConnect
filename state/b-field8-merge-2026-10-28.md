# B field8 累计合并与移动/显示修复

## 用户要求与范围

用户要求合并、验证并部署此前积累的 B 源码；本轮针对双侧移动卡顿、加入侧医疗箱/终端颜色异常、基地背景物件遗漏错位，以及 NPC 文字过大。附图已确认是加入侧异常。只更新 B 独立游玩包，A 和根游戏不属于部署目标。测试使用原有隔离副本、复制种子和独立 AIR 身份，不碰玩家存档或关闭玩家窗口。

## 代码和根因

- 纳入 field6 的差异编码、接收缓冲、场景索引与弹丸记录清理优化，以及 field7 的原生血条/伤害数字描述复用和按房间筛选弹丸发送副本。均保留原生结算、复杂显示回退、同步频率和播放时钟。
- 探索数据合并只在内容真正新增时创建副本，保持历史结果不可变。Python 数据对照覆盖 1,536 组边界、5,000 行、1,200 次累计操作及 1,361,936 次历史数组检查；这只是数据等价证据，不冒充 AS3 实机性能。
- 加入侧缺少 `Location.backobjs` 的真实背景对象，原本只有空 XML 构造的房间。新增原生 BackObj 描述及应用，按实际绘图版本缓存，保留位置、分层、颜色、擦除和光源状态，不重抽地图。
- 医疗箱和终端的资源、颜色本来一致；错误来自 Box 阴影作为松散效果最后加入，同层时盖在本体上。现在阴影归所属 Box 管理，保持原生“先影子、后本体”的相对顺序，避免重复影子。
- 原生对话粒子在出生时已经按相机比例缩放。现在记录真正的出生比例，加入侧按自己的相机比例换算，保留文字自定义倍率；不猜测旧粒子、不改变寿命。
- 实际双侧行走时抓到一次 17px 回跳：新确认迟到超过 150ms 后，加入侧突然撤回本机预测，恢复更旧的播放位置。check03 只保留该次确认下已显示的安全预测位置；超时后不再推算，暂停、危险输入、身份/地形变化立刻废弃，新确认立即接管。停止/反向输入在确认迟到时可能暂时保持该位置，不继续沿旧方向运动。这是受限显示处理，不让加入侧执行战斗。
