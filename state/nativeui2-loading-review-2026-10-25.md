## 加入侧交接与额外重画

`19 后等待`只指 first19→A22 ROOM RECEIVE grant.from，包含原生后续退出、协议调度和对端工作，不能直接称网络延迟。回调耗时含内部 restore；二者不可重复相加。

B 首程相对 A 多 996ms = 开始→20 多 11 + 20→19 多 509 + 19 后多 476。最后 476 = grant 前多 85 + 回调多 408 - 回调后 17。回调多 408 与 restore 的 63→471 完全重合，其中 effects→redraw 多 394。

准确 TerrainSync.restoreCheckpoint 的两种合法快照分支均设置 dirty=true。GameBridge 在该段仅在 terrainView 存在且 unchanged 返回 true 时 refresh、清 dirty、写 terrainReused；否则 tileRedrawIfDirty 调用完整 world.redrawLoc。因此 B 首程确实未复用并进入完整重画路径。**399ms 是比较及重画所在区段的合计，不宣称全部为 drawLoc 独占耗时。** 该轮没有首个拒绝原因数据，无法判定是前置资格、具体地形字段、检查点差异还是新组合的间接影响；不能通过删比较字段或跳状态恢复来消除此分支。

C 首程仍复用，不能替 B 的额外重画消案。基地 B 对 A 加侧多 93ms，主要在 20→19 多 64ms（原生进入多 61ms），其余开始段 +5、19 后 +24；B 对 C 基地加侧还多 41ms，二者 20→19 都为 535ms，差异在后续交接。

## 源码核对与当前判断

9C 与 5325 编译源中的 GameBridge.restoreCheckpoint、tileRedrawIfDirty、roomRole 方法完全相同；RoomTerrainView、TerrainSync、RoomSync、RoomEntryView 整类逐字相同。暂未发现新增直接地形恢复工作；这不排除新代码对执行时机、状态或内存行为的间接影响。不能以 NativeJumpPose 没有调用随机数，推导它绝无影响。

三轮功能与 UI 均通过；仍保留 B 首程额外重画和耗时上升的性能疑点。C 只补充“原9C本身也出现更长原生创建/进入”的事实，不批准性能、不将 B 改判为无回退。下一已准备方向是只记录首拒因、保留全部比较和状态恢复；本记录没有执行该补丁或新增测试。

探针全部采样累计自身耗时（主/加）A=76/14ms、B=96/9ms、C=75/14ms；单次最大 2/2、6/1、6/2ms。这不是整个探针对运行的零扰动证明，也不包含原生工作耗时。
