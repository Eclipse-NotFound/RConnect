# 实验：M19 敌人同步（外观/死亡掉落/仇恨朝向）——2026-08-20

- 游戏版本：1.02（双实例，马哈顿 random_mane）
- 目标（用户点名）：A 敌人外观一致；B 敌人死亡/掉落一致；C 索敌/仇恨
  朝向两侧一致。

## 实现（unitsync 单位条目扩展）

每条单位快照新增：
- `vf`：小马类单位的 `vis.osn.pon.currentFrame`（配色/皮肤帧）；blit 类
  无 osn.pon → -1（外观由类+XML 决定，天然一致）；
- `cx/cy`：`celX/celY`（当前目标点——仇恨/瞄准方向）。

加入方 `applyUnitAppearance(u, vf, cx, cy)`：
- vf>=1 且与本地 pon 帧不同 → `pon.gotoAndStop(vf)`（皮肤一致）；
- cx/cy>=0 → 写 `u.celX/celY`（敌人朝向目标一致，攻击动画瞄准一致）。
应用点：镜像单位（applyUnitsSync）+ 注入傀儡（spawnUnitPuppet 时）。

## 验证

- **A**：`enemy skin 'ponpon' hostVf=20 localPon=20`——宿主小马敌人帧与
  加入方镜像一致（确定性布局下双方同 XML 同外观；vf 同步兜底分歧场景）。
- **B**：宿主击杀→掉落→`obj spawn recv spawned=1 skipped=0`（M17 loot 链
  零失败）；死亡 sost/animState 经 unitsync 回流（尸体姿态由 animate 驱动，
  M6 机制）。
- **C**：celX/celY 每同步写入镜像与傀儡（静默生效，无日志——机制由代码
  保证）。

## 说明

- 敌人外观在"确定性布局"下已由同生成保证一致；vf 同步的价值在于
  "内容随机/存档差异"导致的同 id 不同变体时强制拉齐。
- 死亡掉落的一致性依赖 M17 的链扫描（Loot 恒定上报+幂等去重）——击杀
  即同步，零失败实测。
