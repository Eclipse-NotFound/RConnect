# 实验：M24 可移动物品（Loot）全量同步——2026-08-28

- 用户诉求：完成敌人与可移动物品的同步。
- 敌人侧盘点结论：M4（位置/姿态/血量 5Hz 镜像）+ M8（注入/移除，含空列表
  保护）+ M19（皮肤/死亡掉落/仇恨朝向）+ M10（战斗/死亡复活）已闭环，
  无结构性缺口；敌人死亡掉落的"物品层"正是 M24 补齐的对象。
- 物品侧缺口（M17b 遗留）：键含坐标 → 物品被推动即"新键"→ joiner 重复
  生成+旧位置残影；宿主捡起后 joiner 副本永存；移动完全不同步。

## 机制查证（反编译 1.02）

- `Loot.take(param1)`：强制拾取路径 → `loc.remObj(this)` +
  `World.w.invent.take(this.item)` + `isTake=true`——remObj 即官方移除。
- `Loot.step()` 每帧 `vis.x=X; vis.y=Y-dery` ——直接写 X/Y 后视觉自跟随。
- **`Item(param1,param2,param3)` = (tip, id, kol)——param2 赋给 `id` 而
  非 `base`**（base 字段另有来源；实测 hook 生成的物品 base 恒为 ""）。
  物品身份键应读 `item.id`（读 base 会全空 → spawnLoot 的空 base 卫兵
  直接拒生成，且静默无日志）。
- Loot 生命周期可短于 unitsync 广播间隔（200ms）——"生成即被捡"的物品
  可能永远不出现在任何广播里（对同步无影响，但测试钩子要注意窗口）。

## 方案（M24：稳定身份 + 双向镜像）

- **宿主**：`readLootSync()` 沿 Pt 链枚举 Loot，`Dictionary`（对象键）
  发稳定键 `L#n`（首见顺序），随 unitsync `loots` 数组广播 {k,x,y,b}。
  **空数组也必发**——"缺席"就是移除信号（否则 joiner 永远收不到清理，
  实测会无限重复上报 picked）。
- **joiner**：`applyLootSync()`：
  - 键已知 → 直接镜像位置（写 X/Y，清 dx/dy 防双端物理分叉）；
  - 键未知 → 先"认领"（同 base 且距广播位置 <40px 的未标记本地 Loot
    ——确定性世界里两边同物），认领不到则按 base 构造生成（M17b 同款）；
  - 上次广播有、本次缺席的键 → `loc.remObj` 移除（TCP 可靠有序，缺席
    即真移除，无丢包抖动）。
- **joiner→host 上报**（1Hz，`MSG_LOOT` 新消息）：
  - picked：已标记 Loot `isTake==true` 或从链上消失（joiner 自己捡了/
    本地清除）→ 宿主 `remObj`；
  - moved：位置偏离宿主上次广播 >25px（限频 1s/键）→ 宿主按键落位
    （宿主仍权威）。
- **与 M17b objSpawn 的系统集成**：readNewObjs 不再上报 Loot（原坐标键
  体系退役），Loot 归 M24 单一通道，否则双重生成。
- 敌人补充：死亡掉落物（M19）天然走本通道——宿主掉落 → joiner 生成镜像
  → 任一方捡起全端消失。

## 验证（双实例 m24_run9，begin/loc0_0，9 轮迭代）

全链路日志闭环：
- `loots tx first 1 k=L#1` → `loots rx first` → `loot spawn 'L#1'
  base=kofe`（生成镜像）；
- `lootTest pushed 'kofe'` → `loot move 'L#1' -> 1146,590`（位置镜像）；
- joiner `lootTakeJoin taken 'kofe'` → `loot report picked=1` → 宿主
  `loot pick applied 'L#1'`（拾取上报→宿主移除）；
- 宿主 `lootTest taken 'kofe'`（宿主拾取）→ joiner `loot removed 'L#1'`
  （移除广播→joiner 清理）；
- 重复上报消失（空广播修复后）；零错误对话框、心跳健康。

## 迭代中的坑

1. **测试钩子阶段竞速**：把"生成/推/捡"放一个函数由 Session 每 tick
   调用，phase 自动推进——物品只活 2 个 tick，完美躲开每 4 tick 的
   unitsync 广播点（50ms 生命周期 vs 200ms 采样窗）。拆成三个独立钩子
   各自门控后解决。**钩子的动作窗口必须 ≥ 广播间隔。**
2. **Item.id ≠ Item.base**（见上），读错字段 → 空 base → spawnLoot
   静默拒绝（空 base 卫兵无日志）——静默失败点要配诊断日志才好找。
3. **"缺席即移除"必须真的发空数组**：宿主清空后字段整个消失 = joiner
   收不到信号 = 无限重复上报。
4. AS3 `Object` 做对象键会被字符串化（全部撞键），对象身份映射必须用
   `flash.utils.Dictionary`。
5. ASC 老怪癖再确认：return 全在 try/catch 内 = "函数没有返回值"编译
   错误，一律末尾单一 return。

## 已知限制

- 认领启发式（base+40px）在"两个同 base 物品初始位置重合"时会误认领
  ——确定性世界下仅影响键的归属，不产生物品增减。
- Loot 的 suction 飞向玩家动画（vsos）不镜像，直接落位。
- 宿主权威单向：joiner 推动物品经上报由宿主落位，200ms 内的连续推动
  会被限频合并（1s/键）。
