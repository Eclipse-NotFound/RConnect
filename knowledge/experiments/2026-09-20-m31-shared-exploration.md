# M31：双向共享探索与可选 RV 接口

2026-09-20。用户确认各端独立开关、关闭后保留已收到的区域，并授权同时修改 RV 接口，禁止引入对 RV 的硬性依赖。已执行范围为 RConnect 与 RV 的接口/显示适配；正式 release、游戏 SWF、用户存档和现有游戏进程未由本任务操作。

## 最终行为与实现

- RConnect 0.2.3-dev：删除 M14c 的首次缓存、单向 seen 与原生 visi 改写；独立 `ExplorationSync` 采集当前探索，双向发送。开关控制本人接收，发送仍持续，关闭/断线保留已取得记录。
- 房间键含地图、房间、地图坐标、landStage、宽高；每个本地房间实例有新令牌，收到对方确认本地令牌后才应用。拒绝错房、旧令牌、错误尺寸和编码；地图身份/尺寸在同一对象上变化时使本地共享缓存失效。
- 地图按原版 `space[x][y]` 采集。每格首个十六进制字符是量化光照，后 16 个字符为 64 子格探索位；最多 200×200，完整消息低于现有 1MiB 帧限。最多每 500ms 采集/发送变化，静止时三秒补发快照；没有再挂到 20Hz WORLDSTATE。
- 原版绘制在帧末向 lightBmp 合成远端亮度，不写 visi/t_visi；保留 retDark 例外和本地交互/瞬移条件。
- RV v0.30.0-candidate 发布动态探测 API：active/capture/merge。共享记忆按 Location 实例另存，current 使用子格并集，classic 使用瓦片记忆，墙面使用独立显示光场；保持本地 FOV/currentSight 和原版字段不变。未收到共享时保持原有算法。
- 双方均不 import 对方类、不加载对方 SWF、不引入链接依赖。RConnect 缺少接口即使用原版适配；RV 可单独运行。关闭/vanilla/基地透传会声明原版路径。旧 RV 自建雾层没有新 API，不声称其共享显示已兼容。
- F10 和可用的模组设置页提供同一持久化开关；优先新 `ModSettingsCarrier`，再探测既有 `MSWModAPICarrier`。未修改设置提供者。接口契约保存在 RV 的 design/shared-exploration-api.md。

## 失败与修正

1. 首次接口测试出现 #1056：普通 Sprite 不允许临时写 api 属性。改为带明确 public api 属性的 RVExplorationCarrier；之后独立夹具通过。未把这个失败构建部署。
2. `bb3fcccaeb` 无 RV 首轮：共享 18 项全过，但动画观察窗口在同步夹具工作完成前开始，遗漏中间帧；宿主固定时刻死亡验收也早于加入方真实致死消息。日志保留后续伤害实际到达，不能把此轮整体判通过。
3. `c073575605` RV 首轮：共享 22 项与 TCP 闭环通过，动画时间窗口仍失败。最终把运动快照与 250ms 观察窗口移到首个实际 ENTER_FRAME 启动，保留原有“至少两帧/两个位置状态/动画像素变化/终点”断言；宿主/加入方完成判定等待实际死亡状态，仍有超时失败条件。
4. 修正后无 RV 运行 `c5a976c81c` 为 103 PASS / 0 FAIL，动画实际采到 9 帧、6 个位置状态。此后补充地图对象复用时的身份/尺寸缓存保护；最终 RV 组合与普通候选启动检查覆盖最终构建，详见 JSON。

## 验证边界与交付状态

共享历史保留到当前世界/房间生命周期结束，不新增磁盘历史持久化。未承诺所有房间/Boss/公网/多人/跨版本、最大 200×200 地图长期性能或全部模组组合已验证；既有 M30 的特殊武器边界仍在。

RV 工作树同期出现另一任务的 ModSettings 注册迁移。本任务保留该改动，不将其混入共享探索源码提交；联测候选按实际工作树构建，记录源码/产物指纹。正式部署应在设置任务合并后核对最终构建，不能直接用旧产物覆盖并行任务的新版本。

本轮只交付源码、文档和 build 内候选，未写 release。当前安装仍按 M30 / RV v0.29.0 的原部署记录解释。用户需另行部署候选后才能在正常游戏加载新功能。
