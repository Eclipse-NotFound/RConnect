# M38：战斗伤害、原生姿态与交互响应

用户反馈：轻机枪对尸鬼无效，加入侧受伤疑似偏低；敌人攻击、密集敌人和门柜动画不流畅；炮塔伤害异常；血翼休息姿态追人。本轮继续既有修复和候选部署授权，不扩展多人、公网、跨版本、任务或交易同步。

当前状态：2026-09-28已部署M38 / 0.2.10-dev，最终同字节候选8组391 PASS / 0 FAIL，正常加载双端冒烟通过。密集敌人的整体掉帧仍是已知未完成项。

## 已确认原因

1. 尸鬼原生埋地状态将 `scY` 置0；只同步位置/动画不会恢复子弹碰撞高度。恢复宿主尺寸并重新计算碰撞框后，同进程原生轻机枪45与镜像45一致。
2. 完整TCP仍有另一层失败：`Unit.vulner` 数组混有原生XMLList。直接JSON得到字符串 `XMLList`，计算返回NaN但不扣HP。数值化后真实双端45/45、宿主HP2000→1955，只有一次结算。房间检查点的 `vulner/begvulner` 同时修正。
3. 原受伤链路把化身NPC扣血量当普通伤害再次交给UnitPlayer，丢失元素类别、穿甲与暴击等信息。RemoteDamageUnit收集原始命中，NativeHit保留所需弹体/武器参数，由实际本地UnitPlayer计算一次；下一次同步计时器发送，交接房间前用同一入口清空待发命中。
4. `animState` 字符串不等于显示状态。血翼animate读取内部AI；提前写同名animState又会让原生方法跳过goto。现传原生AI/播放状态，镜像只推进画面；房间恢复也恢复姿态。炮塔展开/收回仍由专门的原生显示逻辑处理。
5. 开门原需连续10个相同快照，本地操作也延迟6次扫描。现首次更新即应用，本地尚未确认的操作保留到匹配回声；重复快照不重新启动显示。
6. 负载下AIR计时器会合并回调，旧“每4次回调”将200ms发送拉长至400–550ms，超过旧插值上限。改为实际经过时间调度，不积压补发；武器位置/角度逐帧插值，动画内gotoAndStop不再递归触发整房显示扫描。

7. 部分机关通过`Box.bindUnit`向`loc.units`注册无图像的`VirtualUnit`，原生不把它放入step/绘制链。交接误将它作为独立敌人重建，putLoc赋予房间变色数据后，addVisual访问空vis导致#1009。现敌人快照与清理排除此类型，保留场景物体的原生受击对象和owner关系。

## 验证方法与边界

外部CombatStateTestDoc对照原生与镜像；CombatNetworkTestDoc经实际Session/TCP，使用原生Weapon/Bullet碰撞炮塔化身，接收端另算原生UnitPlayer参照。伤害参照固定暴击/分解随机项并避免伤势分级，不在生产代码里禁用这些机制。核心测试不以手工修改HP代替命中。

80敌人压力场景仍有明显整体掉帧。前期候选8秒约84–97帧；每帧动画与末尾可见性维护合计约0.5秒，不能以这个局部计时证明整帧成本或其他模组具体责任。旧版同场景瞄准样本数等于收包数，新版约78–93个独立角度、26–34个包，证明包间推进，不等于达到30FPS。

机器还有本任务之外的AIR实例运行；只做了只读进程计数，未干预它们。因CPU/显卡负载未完全隔离，这些帧时长不是独立双实例性能基准，也不能用前后FPS直接推导改动的性能增减。

final5 的2224c642d8真实TCP检查33项通过：原生/加入侧/宿主轻机枪均45，五种炮塔弹种均与原生一致。少敌人252帧/8428ms，p95=46ms；80敌人105帧/8秒，p95=114ms、最长141ms；34包、最长包间隔357ms，101个独立瞄准角度。压力断言未放宽，数据仍属于有外部负载的功能压力观测。

未穷举Boss、自定义第三方攻击、反伤对象上下文和全部特殊武器组合。NativeHit保留当前原生伤害入口所需参数；源单位为本地临时原生Unit，不能称作复原了完整敌人对象图。

正常加载仍记录原有`Area`对象注入参数不匹配后跳过的诊断。旧0.2.9对照a062392e1d、c267170347中也存在；本轮未改造Area构造路径。391项通过指下表覆盖的行为与相应错误检查，不表示原生日志里没有任何历史诊断。
