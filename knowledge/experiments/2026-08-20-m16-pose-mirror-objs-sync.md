# 实验：M16 姿态镜像 + 物品/箱破坏同步——2026-08-20

- 游戏版本：1.02（双实例，马哈顿 random_mane / 基地 rbl）
- 用户诉求：加入方"真实存在于宿主的存档"——房间/物品/破坏由宿主程序
  权威计算并复制过来。报告：幽灵仍趴姿；宿主破坏的物品/房间不一致。

## M16a：趴姿"根因终确认" = 待机标签用错了

- 反例诊断：加轻量探针后发现——**本地玩家静止时的 osn 标签是 `free1`
  （游戏真正的站立待机动画，且会轮换 free1/free2/free3）**；而此前的
  driveVisAnim 把"静止"硬映射为 `stay` 标签，**visualPlayer 的 "stay"
  恰是蹲/趴姿态** → 幽灵静止必趴。M14a 修复的是"标签不切换"，
  切换目标本身是错的才是趴姿。
- 修复：快照携带本机 `vis.osn.currentLabel`（=`pose`）；driveVisAnim
  **优先镜像对方真实标签**（含 free1/2/3 待机、蹲、跳、走），delta
  启发式仅作旧客户端兜底。验证：宿主侧幽灵 osn 显示 `free3`（对方真实
  待机标签），站立正常。

## M16b：物品（箱/门）状态同步

- 确定性布局下双方同模板同 id → 只需同步**状态**（dead/door/hp 等）：
  - 宿主 `readObjsSnapshot()`（loc.objs：id/X/Y/dead/door/door_opac/shelf）
    随 unitsync 广播；
  - 加入方同房 `reconcileObjs` 按 id 镜像（dead 翻转自动换破坏视觉）。
- 验证：objs 同步 33/33、58/58；宿主 `boxKillTest destroyed 'septum'`
  → 加入方 `box destroyed synced 'septum'`（端到端破坏同步）。

## 仍然限制

- **墙体/瓦片破坏（爆炸轰出墙洞）**未同步：tile 的 phis/视觉变化仅宿主侧，
  需"瓦片状态差分广播 + 触发 Grafon 重绘"，属下一课题。
- 物品**新增/生成**（宿主脚本现场生成新物品）未镜像（现状镜像的是同 id
  状态；生成类需 host spawn 广播，待做）。

## 教训

- 复活一个"看起来没在做"的现象时，先看**正确的参照系**（本地玩家自己
  osn 标签），别想当然映射到自造标签集——游戏有自己的 idle 标签体系
  （free1..free3）。
- "让对方镜头里自己真实存在"的正确姿态路径 = 直接转发对方当前渲染标签。
