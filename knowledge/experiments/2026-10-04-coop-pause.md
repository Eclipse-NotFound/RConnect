# 设置和 SATS 的联机暂停

当前：暂停源码已按最小差异合入当前开发树，原型专项通过；尚未据此声明部署或联合候选验证完成。原 RConnect 会话统一版本、最终验证、部署、MEMORY/journal 和提交；R2 负责敌人抓持，R3 负责暂停。编译/AIR 窗口串行使用，测试只使用唯一标识的新角色副本。

## 规则与实现范围

- 用户要求加入“允许打开设置/SATS暂停游戏”的开关，已明确回答“双方一起暂停”：任意一方打开后两端暂停，分房也暂停，双方都关闭才恢复。
- 实现采用两个独立开关 `pauseMenus` / `pauseSats`，内置默认关闭，保留原有行为。F10 中由宿主调整并保存，加入侧显示宿主当前设置。这些是实现选择，并非用户另外指定的保存格式或键名。
- 菜单开关按提问中的推荐方案覆盖原版暂停界面：PipBuck 设置、背包、地图等，以及原生 stand/guiPause/游戏内主菜单。用户尚未另行缩小菜单范围；不把 F10 联机面板本身当作原生暂停菜单。菜单范围为当前实现假定。
- 关闭同步开关不会取消游戏自身对本机菜单的暂停。开启时追加全队暂停。显示独立于 F10 可见性的暂停原因条，保留中英俄文本。
- 暂停期间网络、聊天、菜单操作与 SATS 选目标/确认继续工作；确认的攻击等双方暂停原因全部解除后由原版执行。手动传送和自动跟随不得在联机暂停中移动角色。
- 房间交接、地图切换和死亡流程优先，暂停不拥有或清除 `World.onPause`。断开只清理联机暂停原因，仍打开的本机菜单由原版保持。

## 原生机制与接点

`World.step` 只有在 `allStat == 1 && !onPause` 时运行 `land.step`、死亡/退出步骤、SATS 的战斗/AP更新等；界面部分在 `allStat >= 1` 时运行，并根据 pip/sats/stand/guiPause 重算 allStat。MainMenu 打开时则不调用 World.step。直接停 Stage 或 Session 的 Timer 会连菜单/网络一起停，无法正常关闭或恢复。

`CoopPause` 只订阅已经认证的 TcpLink。客户端报告本机原生菜单/SATS原因，宿主按开关取双方原因的并集并广播；连接身份、递增序号、地图 epoch 过滤陈旧消息。客户端打开允许的界面会立即请求暂停，关闭则等待宿主确认，不能提前清除另一人的原因。没有以短墙钟超时擅自解除仍连接队友的暂停。

帧前优先级 99500，帧后 -7000，位于 RoomSync 的前处理之后、EnemyGrip 的 99000/-8000 之前。需要暂停且 allStat 为 1 时暂设为 2，原生 UI 步骤继续；帧后仅归还自己留下的临时状态。不会把 RoomSync.roomHold 借作联机暂停，也不写 world.onPause。

公开接口：`Session.pause.paused` 为当前有效联机暂停；`requested` 在本机按有效开关请求暂停、尚未确认时也为真；`blocked` 还包含 RoomSync.busy。R2 的 EnemyGrip 据此保留抓持，暂停牵引、耗魔和抓持超时预算；未开启全队暂停时，本机菜单的零耗魔远程抓持由 R2 释放。

GameBridge 保持真实采样时间，显示插值在暂停点取样，停止镜像单位的手动动画推进与索敌辅助；ProjectileVisuals 冻结自身显示时钟，恢复时补偿普通投射物的本地存活时间。原生 MovieClip 和 UI 动画并未统一强行停止，不声称所有装饰动画逐像素静止。

生产合并保留了 R2 的 Session.stop/RoomSync.hold 抓持清理、GameBridge 稳定键/抓取属性/光晕接点。未覆盖整个旧基线文件，未改 R2 的 EnemyGrip、原生存根或测试。测试入口增加 `CoopPauseTestDoc`，其 Pt 声明单独外部编译，不嵌入生产或驱动的原生同名类。
